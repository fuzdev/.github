# fuzdev/.github

> the fuzdev org's public face on GitHub: the org profile and the default community health files

This is the special `.github` repository for the
[fuzdev](https://github.com/fuzdev) organization. GitHub reads it in two
ways, and both are the whole point of the repo:

1. **Org profile.** `profile/README.md` renders at the top of
   [github.com/fuzdev](https://github.com/fuzdev), above the pinned repos.
   It's the first thing visitors see, so it presents the Fuz stack. The
   canonical stack page is [fuz.dev/stack](https://www.fuz.dev/stack); the
   profile README is its GitHub-flavored companion and links to it rather
   than competing with it. Only this exact path is the profile: a `README.md`
   at the repo root shows on this repo's own page, not on the org page.
2. **Org-wide defaults.** `CONTRIBUTING.md`, `SECURITY.md`, and
   `CODE_OF_CONDUCT.md` apply to every fuzdev repo that lacks its own copy.
   GitHub surfaces them in each repo's issue and PR flows and Security tab.

There's no package manifest, no build, no tests, no CI. The one moving part is
the generated profile README, below; everything else is hand-written markdown,
and the only "check" is reading the rendered result on GitHub after pushing.

## Files

```
profile/
  README.md           # org profile, rendered at github.com/fuzdev — generated, don't edit
  README.gen.md.ts    # its gro gen: presentation only, data comes from fuz.dev
  logo.svg            # the Fuz spider, copied from fuz.dev's static/logo.svg
CONTRIBUTING.md       # points to fuz.dev/contributing and the code of conduct
SECURITY.md           # how to report a vulnerability
CODE_OF_CONDUCT.md    # applies to all Fuz projects
*.local.*             # per-machine scripts, gitignored
```

## The generated profile

`profile/README.md` is generated by `profile/README.gen.md.ts`, which imports
the stack data (`stack_layers`, `foundation_groups`, and the status and
language legends) directly from the sibling checkout at
`../fuz.dev/src/routes/stack/stack.ts`. That file is the single source of truth
for what the stack contains; fuz.dev's `/stack` page and this README are two
renderings of it. Editing the stack means editing stack.ts in fuz.dev, then
regenerating here:

```bash
gro gen profile/README.gen.md.ts   # regenerate (gro is installed globally)
gro gen profile/ --check           # verify the committed README matches
```

Gro runs here without a manifest because the gen imports only relative paths
and a type from `@fuzdev/gro`, which is erased at runtime. It needs the fuz.dev
checkout beside this repo; there's no fallback. Commit the regenerated README
with the fuz.dev change, so the org page never shows a piece the site doesn't.

The gen file owns everything that isn't data: the hero, the intro prose, the
section ordering, how a piece renders as a line, and the footer links.

## Conventions

- **Keep it pointing outward.** These docs link to fuz.dev for anything that
  can change (contributing process, stack details) instead of duplicating it.
  Short files that stay true beat long ones that drift.
- **Writing voice** matches fuz.dev and the package READMEs: plain, direct,
  lowercase-friendly, no marketing register.
- **GitHub-flavored markdown only.** No external badge services or hosted
  images; assets live in `profile/`. Code spans stand in for chips, emoji is
  fine sparingly, mermaid renders natively if a diagram earns its place.
- Pushing publishes immediately. Everything here is public.
